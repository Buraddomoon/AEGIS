# Revisão de segurança e confiabilidade — 2026-10-20

Revisão especializada somente leitura do backend/infraestrutura, seguida de correções e verificações locais. Não equivale a pentest independente ou garantia de ausência de vulnerabilidades.

| Achado concreto | Resolução / evidência |
|---|---|
| Migração NOT NULL falharia em banco com runs existentes | Default temporário false e remoção posterior; teste downgrade/upgrade com campanha populada e alembic check |
| Recuperações concorrentes poderiam liberar nova reserva do laboratório | Lock run antes de lab, refresh sob lock e comparação da reserva antes de escrever; ordem consistente com início/cancelamento |
| Limite Wazuh aplicado após download completo | Streaming com limite acumulado de 8 MB e fechamento da resposta |
| Endereço IPv4 mapeado poderia contornar validação de IP | Validação também de ipv4_mapped; regressão com ::ffff:127.0.0.1 |
| Senhas bootstrap com espaços não coincidiriam com schema que fazia trim | Login/UserCreate preservam whitespace; teste API cria/autentica senha com espaços |
| Hash de relatório poderia divergir do JSON entregue por representação de datetime | Normalização JSON antes de SHA-256; teste recalcula hash diretamente do conteúdo recebido |
| Título Sigma excessivo causaria erro de comprimento no banco | Limite explícito antes de persistir; regressão de título com 241 caracteres |
| Aplicação compartilhava credencial administrativa SQL | Papel aegis_app independente, NOSUPERUSER/NOCREATEDB/NOCREATEROLE; evidências/auditoria/versões sem UPDATE/DELETE; verificação real no container |

Pendências que bloqueiam execução real: chamadas de adapters bloqueantes precisam de timeout/interrupção efetivos em isolamento de processo; lease/fencing para efeitos externos; identidade interna de Asset precisa de tradução explícita para Wazuh agent.id; polling real de ingestão e teste autorizado com SIEM. Demo não possui efeitos externos e nenhum adaptador real foi habilitado.

Advisory transitivo DiskCache: ocorrência moderada conhecida, sem patch upstream na pesquisa; o caminho de parsing usado não importa o pacote nem cria cache. Ocorrência permanece visível, com baseline explícito e regressão dessa premissa. Não alegar zero achados.

## Revisão de agendamento Demo

Revisão especializada somente leitura identificou expiração antecipada após último slot busy/late, corrigida para EXHAUSTED com regressão que preserva a run anterior válida. Pausa e dispatcher serializam pelo plano; worker lê grant sem row lock para evitar deadlock. Cada run valida sua autorização original e cleanup continua após revogação.

Também corrigidos planos pendentes/pausados expirados consumindo quota e DELETE runtime de planos/autorizações. Campos imutáveis possuem UPDATE revogado, com grants somente de estado/contador e revogação. A validação inclui smoke Compose real com aegis_app, além de testes com schema owner. Nenhum executor real habilitado.
